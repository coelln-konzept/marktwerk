# Research 10 — UX/UI review and industry comparison (October 2026)

*Session 7, 2026-10-29. Ten desk-research tracks on comparable products and design systems, ten hands-on audits of
the running app (Playwright with Chrome, 1440 / 768 / 390 px, light / dark / compact, keyboard only, axe-core 4.10),
then fixes in thirteen parallel work packages and a verification round. The detailed reports with screenshots stayed in
the session scratchpad; this file keeps the conclusions. Earlier research (01–09) was not repeated. Evidence quality:
vendor help centres and design-system docs were read directly where reachable; review sites (G2, Capterra) and several
vendor apps (Cvent, Momentus, Crescat, monday, Personio) were blocked or JavaScript-only, so some comparisons rest on
search snippets, marked "(snippet)".*

## 1. Where marktwerk stands against the industry

| Area | Comparable products looked at | Finding |
|---|---|---|
| Market organiser software | Marketspread, Eventeny, Manage My Market, VOIS\|MARKT, FlohmarktPro, Marketport, Flohmarkthelfer, Crescat, STADTFEST pro | They are booking/stall/fee tools. **None has a per-market readiness layer** (tasks + permits + dates per market) or a cross-market weekend view. VOIS\|MARKT's date generation (rhythm, exclusions, preview, logged run with undo) is the closest to "Markt planen"; ours matches it. Marketspread added a widget dashboard and then "kiosk mode" to restrict it again — supports ADR 0019 (classic screens, no custom dashboards). |
| Event / festival ops | Planning Pod, Aisle Planner, Ticket Fairy EOS, Cvent, Tripleseat, Lennd, Rosterfy (partly snippet) | Anchor-relative task timelines exist ("N days before") but **without preview when the date moves**; marktwerk's Verschieben preview and the Bereitschaft/Matrix views are ahead. Planning Pod's separate "waiting" bucket and Ticket Fairy's close-out ("for next time") are worth borrowing. |
| Work management | Linear, Asana, Todoist, Things, Basecamp, ClickUp, Jira | All keep **state** (my tasks) apart from **events** (inbox); overdue is one vocabulary with words for today/tomorrow; snooze returns by itself; E/X/J/K conventions; undo merges when ticking several items. Grouped lists (not kanban) are the norm for date-driven checklists — confirms the Ablauf view. |
| Templates with relative dates | Asana, monday, Smartsheet, Teamwork, ClickUp, Process Street, Aisle Planner | Asana cannot bulk-instantiate a template and edits reach only projects created afterwards; monday/Wrike have no propagation. Our "Auf Veranstaltungen anwenden" with preview and nothing pre-selected is ahead. Gaps were display ones: offsets only in days, no real dates, a thin "Markt planen" preview. |
| Permit / compliance tracking | Harbor Compliance, PermitFlow, Fleetio renewals, expiry trackers, FilmLA (marketing pages) | Our status model (incl. derived "Vergangen") is richer than most. Industry ties urgency to the **lead time per permit type**, not to the event date — adopted (badge by apply-by). |
| Start screen | Linear, Asana Home, Basecamp, Shopify admin, Stripe home, NN/g dashboards | Single-screen monitoring, "needs attention" cards with "see all", one place for the full list. NN/g: 57 % of viewing time above the fold, 74 % in the first two screenfuls. The Übersicht was 3.7 screens (desktop) / 6.1 (phone). |
| Calendar | Google Calendar, Outlook, Teamup, Notion Calendar, Fantastical (product knowledge) | Phones default to a list/schedule view; same-day overflow is a link; month title jumps; ←/→ navigation. |
| German B2B microcopy | SAP Fiori text rules, Duden, accessibility notes on gender glyphs (vendor guides not reachable) | Neutral imperatives ("Bitte einen Namen angeben"), one generic error, "Status" plural, units "Std."/"Min.". |
| Design systems | Carbon, Atlassian, Primer, Polaris, GOV.UK, Fluent 2 | Toasts: errors never auto-dismiss, pause on hover, keyboard-reachable undo. Forms: "(optional)" instead of asterisks (GOV.UK). Tables: one tab stop per list (roving tabindex), sticky headers. |
| Mobile | Material 3, Apple HIG, WCAG 2.5.8, Linear/Asana/Shopify mobile | 16 px inputs (no iOS zoom), cards instead of sideways-scrolling tables below 640 px, filters behind one button, keyboard hints hidden on touch. |

**Differentiators to keep** (no competitor has them): Bereitschaft and Kernaufgaben-Matrix across markets, "Was fehlt"
per market, the ⚑ weekend-load marker, Verschieben with preview, template propagation with preview and nothing
pre-selected, the derived permit states.

## 2. What the audits found (before the fixes)

Cross-cutting defects with one root cause each:
- `cn()` used plain tailwind-merge, which read the custom `text-tiny` as a colour: every status badge rendered at 14 px
  instead of 12 px and every small primary button had dark text on teal (2.17:1).
- Focus rings were invisible on ~40 controls: in Tailwind 4 `outline-none` (and `outline-hidden`) zero
  `--tw-outline-style`, which cancels `focus-visible:outline-2`.
- A failed server action white-screened the page (no `error.tsx`, no catch around action calls); 19 of 21 routes gave no
  click feedback (no `loading.tsx`); filter selects reloaded the whole document.
- Dark mode failed contrast on every route (white text on the light red badge dot, 3.14:1); form borders were 1.6:1.
- `sr-only` cells escaped table scrollers and widened pages on phones (`/orte/<id>`, event tabs).
- One due state looked and read differently on every screen (four overdue icons; "seit 3 T", "3 Tage überfällig",
  "in 2 T", "In 2 Tagen", "Morgen"; the same "4 überfällig" red on the Board and amber on the Übersicht).
- The Kalender phone default (decided 2026-10-28) had never been built.

Per area, the main ones: Übersicht duplicated the notification center and buried "today" 1,500 px down; the center's
snooze hid only the notification; "Markt planen" would create exact duplicate dates; the permit badge counted 2027
permits nobody can apply for yet while the page opened all green on season 2026; the permit drawer's primary button
went backwards; 70 permit decisions on one day flooded the calendar; template offsets were days only and the apply
sheet had no years; forms marked nothing optional and validated required fields only on the server; the undo toast was
unreachable by keyboard and errors looked like successes.

## 3. Decisions taken (logged in `docs/open-questions.md`, 2026-10-29)
Übersicht "Zwei Fragen" · one due vocabulary (`DueBadge`) · permit badge by apply-by ("Jetzt zu tun") · "Gibt es schon"
in Markt planen · Wartet shows its age only · snoozing a task works everywhere · "(optional)" labels (no inline-error
redesign, no unsaved-changes guard) · stacked toasts with an error tone and Strg+Z · bell badge counts open items ·
late tasks on planning are created as overdue.

## 4. What was built
Foundations: tailwind-merge font-size group, focus rings, contrast tokens (`--on-critical`, `--on-ok`, 3:1 borders),
`touch:` variant and 16 px inputs on touch, `dayDistance` + `DueBadge`, `Label optional`.
Areas: in-shell error page, global error, German 404s, loading skeleton, `callAction`, stacked toasts with Strg+Z ·
skip link, landmarks, modal mobile nav, palette rewrite (all words, word-start ranking, totals, "Alle N anzeigen",
years, phone/e-mail), `?` shortcut dialog, pending nav links, context "+ Neu" · Übersicht "Zwei Fragen" with weekend
verdicts and drawer in place · notification center with task snooze, one ranking, drawer in place, filters on phones
· Kalender phone list, grouped deadlines, jump, ←/→, Ebenen sheet · Markt planen duplicates, step-3 summary, keyboard
calendar, loading/error hints, month headers and phone cards on Veranstaltungen · event tabs on phones, roving tabindex
in all keyboard lists, Ablauf focus, permit drawer on the event, Verlauf with tasks and names, richer Verschieben
preview · permit rule `permitActionTier`, "Kommend" default, apply-by list and matrix, forward-first drawer ·
Board: one Zeitraum meaning, matrix scroll cues, drawer done state / blur-save / undo / optimistic close, new-task
dialog with dated events, Spalten cap + memo · Stammdaten client checks, phone cards with "Anrufen", multi-word
search · Bibliothek "in Gebrauch", offsets in weeks, ruler per anchor, apply sheet years/filter/overdue warnings ·
German microcopy pass · client-side filters and optimistic segmented controls.

## 5. Not done — candidates for later (need a decision or are larger)
- "Vorjahr übernehmen" chip in Markt planen (same n-th weekend as last year).
- "Absagen" with a consequence preview, mirroring Verschieben; close-out card ("Fürs nächste Mal") on past markets.
- Read-only ICS feed for the owner's phone; printable week sheet.
- Typo-tolerant search (`pg_trgm`) for "Flomarkt", "bnon".
- Pflichten reminders in the bell and the Übersicht (the "Erinnerung ab" field only drives the status chip today).
- One apply task per season permit instead of one per covered market (7 identical tasks seen).
- A derived "Antwort überfällig" permit state when the expected decision date has passed.
- Bottom navigation and PWA basics for phones; market-day mode.
- Microcopy decisions: "Markt" vs "Veranstaltung" in UI text, gender forms (Aussteller:innen), "bitte" policy,
  Login vs Benutzer, template vocabulary.
- Archive lists to restore contacts/vehicles after the 8 s undo.
