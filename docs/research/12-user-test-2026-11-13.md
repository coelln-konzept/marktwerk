# Research 12: User test 2 (13 November 2026)

*Source: the product owner's notes from a user test on 2026-11-13. The design below was worked out with the
product owner in the same session. Items have IDs (UT2-xx) so Fahrplan steps, commits and PRs can refer to
them. Decisions are D2-x and are also logged in `docs/open-questions.md` (Decided).*

## 1. Summary
- **Biggest pain: having to leave a flow to create something.** A new Ort can't be created in "Markt planen",
  an Eigentümer has to exist before its Ort, and about 40 pickers across the app are plain dropdowns with no
  way to add a missing entry.
- **Times need a model, not four fields.** Who are Aufbau / Beginn / Ende / Abbau for? There are team,
  vendor and visitor times, and edge cases such as an early tear-down window on the last morning.
- **Tasks:** they must be deletable, and per-task checklists plus dependencies should become **subtasks**,
  as in most task managers, with drag & drop nesting.
- **Smaller:** a Kalender click should open a popover instead of leaving the Kalender; Marktregeln should be
  editable from the event; Ort types are only *städtisch / privat*; "Festsetzung" is its own permit type;
  the Zufahrt section of the Ort form is hard to read; the "other markets this weekend" hint isn't needed.

## 4. Design

### A. Quick fixes
- **UT2-11:** drop `warn.weekend*` from `CandidateNotes` and the "Wochenende voll" marker in step 2; keep the
  venue-busy, overlap and holiday hints. `MAX_EVENTS_PER_WEEKEND` stays in core (the bookable-weekend rule).
- **UT2-05:** one section style for long forms: a stronger section heading with spacing and a divider above,
  field labels visibly smaller. Applied first to the Ort form, then to the forms that reuse the pattern.
- **UT2-06:** new `permit_type` value `market_fixing`, "Festsetzung (§ 69 GewO)", next to
  "Marktgenehmigung (Sondernutzung)". Glossary updated.
- **UT2-13:** `deleteTask` service: permission `task:delete` (granted to staff too), sets status `cancelled`
  (already hidden everywhere) and audits `task.delete` with the previous status, so the undo toast and
  "Wiederherstellen" in the Verlauf restore it. Deleting a parent deletes its subtasks with it (after F).
  Menu item "Löschen" in the task drawer and the card/row "⋯" menu.
- **UT2-12:** `event_preset.rules` (copy of the event type's rules at creation; migration fills existing
  presets). The event page's rules panel gets "Bearbeiten" → a dialog editing the market's rules, with the note
  that it applies to every date of this market. Events without a preset show the type's rules read-only.

### D. Kalender popover (UT2-08)
- Clicking an event chip (Monat) or row (Liste) opens an anchored popover, built like `DayMore` (base-ui
  Popover) with the content of `EventVorschau`: type, status, date with KW, Zeitplan summary (visitor hours +
  "Aufbau ab"), Ort, open and overdue task counts.
- Actions: status menu (Entwurf / geplant / bestätigt via the existing status service and undo toast),
  "Checkliste" link (`/veranstaltungen/[id]/board`) with counts, primary button "Öffnen".
- Linkable: `?vorschau=veranstaltung:<id>` like the Besprechung Vorschau; Esc closes, focus returns.

### B + C. Ort and creating records in place (UT2-01/02/03/04/07)
- **One shared picker** (`RecordPicker`): a searchable combobox (keyboard: type, arrows, Enter) whose last
  option is "+ Neu: ‹typed text›". It opens a **quick-create dialog** stacked on the current dialog or sheet,
  with only the required fields; on save the new record is selected and the user continues. Full details are
  edited later on the record's page. The created record is merged into the picker's options client-side.
- **Quick forms:** Ort (address, city, Städtisch/Privat, optional Eigentümer via the same picker, so a second
  stacked dialog for a new Eigentümer), contact (name, kind, phone/email).
- **Ort name:** optional. If empty, the service derives it from the address ("Stadt – Straße"); the form
  prefills it live and it stays editable.
- **Ort type:** `venue_kind` becomes `municipal | private` ("Städtisch" / "Privat"); migration maps
  outdoor_public → municipal, outdoor_private and indoor → private; template conditions follow.
- **Rollout:** Markt planen / new market / manual event / basics dialog / permit dialog (Ort) → Ort form
  (Eigentümer) → permit drawer (Behörde), agreements (Vertragspartner), payables (Gegenpartei) → the rest.

### E. Zeitplan (UT2-09/10), see ADR 0022
- Row: `audience` (team | vendors | visitors) · `kind` (setup | open | teardown) · `day` (first | each |
  last | before: the day before the first day) · `from` · `to` (HH:mm, Berlin).
- `event_preset.schedule` (defaults) and `event.schedule` (copied at instantiation, editable per event); the
  old `times` stay until every reader uses the Zeitplan, then go.
- Defaults for new markets: Händler Aufbau (first) 06:00–08:00 · Besucher geöffnet (each) 08:00–16:00 ·
  Händler Abbau (last) 16:00–18:00.
- Summary everywhere compact ("08–16 Uhr · Aufbau ab 06:00"); the full Zeitplan on the event page and in
  Markt planen (editable list with add/remove row).
- Validation in core: from < to; "open" rows exist for visitors; rows for multi-day markets may use `day`.

### F. Subtasks (UT2-14), see ADR 0021
- `task.parent_task_id` (exists) is used; **one level**: a parent can't itself have a parent, a task with
  subtasks can't be nested (service + DB check via trigger or service guard).
- **Lists:** every task query lists top-level tasks only (`parent_task_id is null`) and carries
  `subtasksDone/subtasksTotal` and `subtasksOverdue`. The Übersicht flags a parent with an overdue subtask.
  Reminder jobs: an overdue subtask counts once, through its parent; assignment notifications go to the
  subtask's assignee.
- **Done gate:** `missingEvidence` treats open subtasks like open check items today; after the last subtask is
  done, the toast offers to complete the parent.
- **Nesting UI:** in the event Checkliste (Ablauf) and the task drawer: drag a task onto another task to nest
  it, drag it out to the list to lift it out (dnd-kit, ADR 0020); menu alternative "⋯ → Unteraufgabe von…" /
  "Aus Hauptaufgabe lösen". The drawer lists subtasks with tick, title, assignee and due, plus "Unteraufgabe
  hinzufügen".
- **Templates:** `template_item.parent_key` (child items); "Teilschritte" in the item drawer become child
  items; `checkItems` and `dependsOnKeys` are migrated and dropped. Instantiation creates subtasks.
- **Migration:** each `task_check_item` → a subtask (title, done → status done, doneAt, doneBy);
  `task_dependency` and template dependencies dropped (they drive no logic today).

## 5. Data shape for the new synthetic dataset
The product owner is building a new, more realistic synthetic dataset. It should produce, once the steps
below are built:
- **Ort:** `venue.kind` = `municipal` | `private`; `name` may be omitted (derived from the address).
- **Market (preset):** `rules` (same shape as `event_type.rules`), `schedule` (Zeitplan rows as in E).
- **Event:** `schedule` (copied from its market, possibly changed).
- **Templates:** child items via `parent_key` instead of `checkItems`; no `dependsOnKeys`.
- **Tasks:** subtasks via `parent_task_id` (one level) instead of check items; no dependencies.
- **Permits:** may use the new type `market_fixing` (Festsetzung).
